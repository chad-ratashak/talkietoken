Hypotheses
What the vocabulary can settle on its own, and what needs the model to actually answer a question.
Python: leaked, or learned in the prompt?
In-context learning cannot create a BPE merge — code pasted into a prompt leaves no fossil. Corpus leakage must. So the vocabulary is a one-sided test: Python-specific merges present would be strong evidence of leakage; absent only bounds the tokenizer's corpus, never the weights.
The naive version of this test fails, because almost every Python keyword is an ordinary English word. These carry no information either way — and neither does def, which is a word-initial fragment of define, defend, default, deficient.

If the language were not made of English
Python is close to a best case for a 1930 English model: its keywords are English words whose ordinary meanings match their semantics (return, if, while, for…in, sum, len, sort, open). Bar = tokens per character in talkie — the cost of writing the same task in each notation. Ratio against o200k hides this, because o200k has no merges for J or APL either.
Rows are ordered by how much English the notation is made of, and the bars are not monotonic in that order — J has no English at all yet costs less than Perl, because J is terse ASCII. Token cost measures how compactly the tokenizer can write a thing, not whether the model can do anything with it. Only APL is punished by cost alone, and that is byte fallback rather than vocabulary. What it generates
n=3 per prompt at temperature 0.7, verbatim from results/lang-probes.json. There is no o200k model to compare against — o200k is a tokenizer, and its comparable artifact is the split above.

Behavioral neighborhood map (instruction-tuned chat model, single temp-0 sample; modern comparand is a different-family LLM) — not embedding geometry. Frequency ranks are a BPE merge-order proxy, comparable only as percentiles. True embedding-space drift (Procrustes / cosine) still requires the model checkpoint.

The bomb, before and after — token counts are exact and reproducible (tokenizer-only/talkietoken-atomic.py); merge rank remains a frequency proxy, so single-name deltas are noisy and only the cohort pattern should be trusted. The behavioral probes are n=3 per prompt at temperature 0.7 against the hosted instruction-tuned chat model, not the base checkpoint — a period persona can be imitated, which is why the vocabulary evidence is the forgery-resistant half and the generations are illustration. Keyword counts were checked against the raw completions by hand: an earlier pass scored the Los Alamos probe 3/3 for Texas-Alamo confusion because “alamo” occurs in the question itself, and scored Millikan 0/3 for writing “professor of physics”. Both are fixed in the script; keywords appearing in the prompt are now excluded by rule.

Python — the vocabulary test is one-sided by construction: in-context learning cannot create a merge, so absence of Python merges bounds the tokenizer's corpus and says nothing about what the weights saw; the two can be trained on different data. Generation figures are n=3 at temperature 0.7 against the instruction-tuned chat endpoint. The counters measure whether the demonstrated notation was imitated, not whether the program is correct — on this evidence those come apart completely (Python and APL both keep the form 3/3 and are right 0/3). n=3 at pass@1 is not comparable to, and is no refutation of, the cited HumanEval pass@100, which draws 100 samples and counts any single success. Counterfactual notations are one snippet each, chosen by the author; a real version would sample many tasks per language. Sources: tokenizer-only/talkietoken-python.py, talkietoken-langprobes.py.
