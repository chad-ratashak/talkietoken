figure in results/reconstitution-penalty.txt is one cell of this.

The question is not 'what is talkie's penalty'. It is whether that
number is a property of talkie or an artefact of picking o200k, and
whether a model that demonstrably HAS Python scores any lower.

--- HOW TO READ THIS ---
  gpt2 is the POSITIVE control: a tokenizer genuinely worse at
    Python (2019, 50k, web text). It should score high. If it does
    not, the statistic is broken outright.
  cl100k / Llama-3.2 / gemma-2-2b are NEGATIVE controls: current,
    code-fluent, Python unambiguously in the training data. They
    should score ~1.0 if the statistic measures corpus absence.
  talkie-1930 is the model under test.

  The predictor discriminates only if talkie sits ABOVE the
  negative-control band under a common reference. Read the talkie
  row against the cl100k / Llama / gemma rows, one column at a time.

--- DOES IT DISCRIMINATE? (pre-registered) ---
Per reference: talkie's margin over the worst negative control,
against the spread among the negative controls themselves. A margin
smaller than that spread is not evidence about talkie's corpus.

  reference        talkie   neg ctrl band   margin    band   verdict
  gpt2              0.739     0.596-0.691   +0.049   0.095   NOT separated  [dropped Llama-3.2-3B]
  cl100k            1.238     0.996-1.151   +0.087   0.155   NOT separated
  o200k             1.243     1.004-1.156   +0.087   0.152   NOT separated  [dropped Llama-3.2-3B]
  gemma-2-2b        1.076     0.865-0.869   +0.207   0.004   separates  [dropped Llama-3.2-3B]
  Llama-3.2-3B      1.238     0.996-1.151   +0.087   0.155   NOT separated

  separates under 1 of 5 scorable references (0 unscorable for lack of independent controls).

  The row that decides it is o200k: that is the reference the
  published figure uses. The other rows are robustness.

  Caveat on the gemma-2-2b row: a tokenizer cannot be its own
  control, so gemma leaves the control set exactly when it is the
  reference — and gemma is the control that varies most. What is
  left (cl100k, o200k) happens to agree closely, so the band
  collapses and the margin clears it. That row reads 'separates'
  because the widest control was removed, not because talkie stood
  out. Do not count it as corroboration.

  Note: Llama-3.2 and cl100k return identical counts on English and
  Python — Llama-3's 128k vocab embeds cl100k's 100k tokens. They
  are distinct tokenizers (they diverge on Urdu and Hindi), but as
  a Python reference Llama adds no information cl100k did not.
  Treat that column as a duplicate, not as corroboration.
